# 命名、版本与兼容性

## 按层命名

内部原子读取接口/方法采用项目既有 `getXxx` 命名，请求响应用 `GetXxxReqDto` / `GetXxxRspDto`。内部 REST 适配调用方法使用 `invokeGetXxx`。这是内部调用范式，不把 invoke 扩散到原子接口，不把已发布业务工具的 query 名称和外部系统的 query URL 改成 get。

重命名搜索接口、实现、Latest、管理器调用、DTO、转换器、测试及注册配置，核对源码引用和运行绑定。未引用旧类不代表 wire 兼容已验证。业务响应使用当前 RspDto 约定，不能强改历史公共模型名称来适应示例。

## 支持版本

从真实能力首次支持版本定义原子接口及实现，不为新能力增加空的旧版本定义。Latest 必须继承正确版本，注册和动态选择完整；复用已有能力时保留其真实旧版本。版本范围必须由源码或接口契约证明，不根据需求编号或当前分支名推断。验证版本选择时覆盖首次支持版本、后续 Latest 以及较早不支持版本：后者沿用框架既有“不支持”返回或异常路径，不能误选新实现或伪装成功。

## JSON

删除注解前同时检查真实 ObjectMapper 配置、该类所有消费者和外部 wire 字段。注解与字段同名且没有特殊语义才冗余；连字符、大小写差异、命名空间及历史别名必须保留。已有注解也不是 wire 名称的独立证据。

全局已忽略未知字段且覆盖实际消费者时去掉重复类级 ignore 注解；无法确认其他消费者时保留并说明未验证项。不批量删除 JSON 注解，不以本地反序列化默认行为替代实际配置。

## 错误、注释与日志

预期业务失败使用 OpsApiException。英文错误应指出操作、必要标识与底层原因。保留既有失败返回形式：任何已发布接口若约定返回失败字符串，就保留英文 String 响应；其他接口按既有 ServiceException 适配。保持异常 cause，不新建不必要的通用异常层。

注释精炼中文，解释职责和业务意义；版权头与日志 API 沿用真实仓库。entry/ret 如有项目约定应成对，不为打印 ret 强加 try/catch，不把敏感请求放进日志。不要新增解释性层级、无业务含义的抽象或冗余保护分支。

## 处理审查意见

先确认意见适用的层和最终结论。后续明确采用 Converter 时，旧的“私有节点转换方法”方案不再作为并行规范保留。每次反馈按授权边界小步修改并检查调用链，不自动回滚其他已接受改动。用户豁免的 MR 拆分和暂停测试要求在当前任务内有效；不从 skill 推导额外确认流程。
